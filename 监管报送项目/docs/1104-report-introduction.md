# 1104 非现场监管报表介绍

> 更新日期：2026-05-18  
> 适用项目：监管报送项目 / 一表通主线重构  
> 文档定位：作为后续从“监管发文加工助手”调整为“监管报送数据标准与一表通改造助手”的 1104 基础说明文档。

## 1. 结论概览

1104 报表是银行业非现场监管报表体系的核心组成，主要面向银行业金融机构的经营、风险、资本、流动性、业务结构、普惠金融、绿色金融、重点领域投向等监管主题，按照监管规定的机构范围、并表口径、报送频度和上报时限定期报送。

结合当前目录下 2025 年“一表通/非现场监管报表”材料，1104 可以先按三层理解：

| 层级 | 含义 | 对系统建设的意义 |
|---|---|---|
| 报表制度层 | 报表编号、报表名称、填报机构范围、并表口径、频度、时限 | 建立监管报表目录、版本、适用机构和任务日历 |
| 表样与口径层 | 表样、行列项目、填报说明、指标定义、口径解释 | 建立指标口径库、字段映射、加工规则和校验规则 |
| 数据落地层 | 源系统数据、明细数据、汇总加工、审核、报送、差错整改 | 建立数据血缘、自动取数、可信区、质量校验和复核闭环 |

在“一表通”背景下，1104 不应再被理解为单独的 Excel 报表填报工作，而应被放入统一监管数据工程中处理：一表通以明细级、标准化、可穿透的数据底座为目标，未来 1104、EAST、客户风险等既有报送体系可能逐步通过一表通数据转换、拆分、验证和替代。因此，本项目主线建议从“发文解析 + 工单流”调整为“监管数据标准 + 报表口径 + 字段映射 + 校验治理 + 报送运营”的产品结构。

## 2. 一表通背景下的 1104 定位

公开行业资料显示，国家金融监督管理总局已建立银行机构监管报表“一表通”数据标准及配套管理体系，并在部分银行和部分金融监管局开展试点，目标包括推进监管数据标准化、打破数据壁垒、提高监管数据整合采集能力、支撑监管大数据平台应用和全流程线上监管评级。

2025 年公开行业解读提到，监管侧推进“一表通 2.0 正式版”，并要求银行机构做好数据报送准备、建立监管可信区、推进数据源统一、适配转换工具和完善管理制度。其中特别值得关注的一点是：一表通与 1104、EAST、客户风险等报送体系关系紧密，银行需要通过一表通数据质量校验和转换验证，逐步支撑现有报送体系的替代或并行压降。

对本项目而言，1104 与一表通的关系可以这样表达：

| 体系 | 当前特征 | 一表通重构后的关注点 |
|---|---|---|
| 1104 | 以监管报表、指标、汇总口径为核心 | 从明细数据自动加工生成监管指标和报表结果 |
| EAST | 以标准化明细数据采集为核心 | 与一表通资源层/穿透层存在更强的数据项、主题和明细映射关系 |
| 客户风险 | 以客户、集团、风险暴露等维度为核心 | 与客户主数据、关联关系、授信和风险暴露主题贯通 |
| 一表通 | 以统一数据标准、可信区、穿透监管和数据复用为核心 | 成为监管数据底座，承接 1104/EAST/客户风险等报送转换与校验 |

因此，1104 在新主线中不是被废弃，而是作为“监管指标与报表口径层”的重要输入：系统需要能管理 1104 报表目录、填报说明、指标口径、机构范围、频度时限，并将其与一表通明细数据、内部源系统字段和质量校验规则关联起来。

## 4. 1104 报表体系结构

### 4.1 基础类、业务类、支持发展类

以 `附件1-1` 的一组法人银行业金融机构为代表，基础类、业务类、支持发展类报表去重后共 69 张/项：

| 类别 | 数量 | 主要主题 |
|---|---:|---|
| 基础类报表 | 44 | 基础财务、股东情况、资本充足、杠杆率、信用风险、流动性风险、市场风险、国别及区域性风险等 |
| 业务类报表 | 11 | 表外业务、衍生品、理财、互联网贷款、股权质押、银行卡、融资工具发行、负债业务、投资业务、信贷资产转让等 |
| 支持发展类报表 | 14 | 重点行业、制造业、普惠金融、小微企业、绿色金融、三大工程、科技金融、养老领域、数字领域等 |

从境内汇总口径看，频度分布如下：

| 频度 | 数量 | 说明 |
|---|---:|---|
| 月报 | 19 | 多为基础财务、贷款质量、房地产融资、制造业、普惠小微等高频监测事项 |
| 季报 | 44 | 多为资本、风险、业务结构和支持发展类统计事项 |
| 半年报 | 3 | 主要涉及股东、押品、存款客户等相对低频事项 |
| 年报 | 3 | 主要涉及操作风险历史损失、损失事件分布、境外机构设立等事项 |

### 4.2 机构类报表

`附件1-5` 统计到机构类报表 110 项，覆盖政策性银行、国家开发银行、邮储银行、农业发展银行、城市商业银行、外资银行、理财公司、金融资产投资公司、信托公司、企业集团财务公司、金融租赁公司、汽车金融公司、货币经纪公司、消费金融公司、金融资产管理公司、金融控股公司、农村合作机构、新型农村金融机构等机构特色监管场景。

机构类报表的特点是“机构适配性强”：不同机构的业务模式、资产负债结构、风险类型差异较大，因此不能只按统一 G/S 报表编号处理，系统需要维护“机构类型 - 适用报表 - 口径 - 频度 - 数据源”的关系。

## 5. 关键报表主题

1104 报表不是一张表，而是一套监管指标和报表集合。对银行内部系统来说，可以按以下主题建模：

| 主题 | 典型报表 | 关注内容 |
|---|---|---|
| 基础财务 | G01、G01 附注、G03、G04、G05 | 资产负债、存贷款明细、减值准备、利润、个人贷款 |
| 资本与杠杆 | G40、G44、G4A、G4B、G4C、G4D | 资本充足率、杠杆率、风险加权资产、市场风险、操作风险 |
| 信用风险 | G11、G12、G13、G14、G15、S67 | 五级分类、迁徙、押品、大额风险暴露、关联交易、房地产融资 |
| 流动性风险 | G21、G22、G23、G24、G25、G26 | 期限缺口、流动性比例、存款客户、同业融入、LCR、NSFR、优质流动性资产 |
| 市场及区域风险 | G32、G33、G51、G52、G53 | 外汇敞口、利率风险、境外业务、地方政府融资平台、分地区情况 |
| 业务活动 | G02、G06、G09、G16、G17、G18、G27、G31、G34 | 衍生品、理财、互联网贷款、股权质押、银行卡、融资工具、投资、信贷资产转让 |

## 6. 报送口径、频度和时限

本地附件中的 1104 报表制度以以下维度约束报送任务：

| 维度 | 说明 | 系统建模建议 |
|---|---|---|
| 机构分组 | 一组、二组、三组、四组法人银行业金融机构，以及机构类、分支机构 | 建立机构分组、机构类型、机构层级、适用报表关系 |
| 填报机构范围 | 不同报表适用于不同机构类型，例如政策性银行、大型商业银行、股份制银行、城商行、农商行、外资银行、非银机构等 | 建立报表适用范围规则，支持按机构自动生成任务 |
| 并表口径 | 境内汇总数据、法人汇总数据（含境外分行）、合并报表数据（含附属公司） | 建立口径维度，区分行内机构汇总、法人口径、集团并表口径 |
| 频度 | 月、季、半年、年 | 建立报送日历和批次管理 |
| 时间要求 | 6 天、13 天、18 天、40 天等 | 生成上报截止日、审核截止日、预警和逾期状态 |
| 表样版本 | 附件 4 中包含 251 版表样和填报说明 | 建立报表版本、表样文件、填报说明和生效年度 |

`附件3` 给出了 2025 年非现场监管报表上报和审核时间表，说明实际运营中不只是“按频度报送”，还存在月报第一批次、月报第二批次、季度/半年/年度批次和审核截止日。系统后续应把“频度规则”和“年度上报审核日历”拆开建模。

## 7. 1104 与数据治理的关系

1104 报表加工链路可拆成以下步骤：

```text
监管制度/表样/填报说明
  -> 报表目录和指标口径
  -> 源系统字段识别
  -> 数据抽取与补录
  -> 指标加工与汇总
  -> 表内/表间/跨体系校验
  -> 业务复核与数据质量整改
  -> 监管报送与审核反馈
```

在银行内部，1104 的难点通常不在“生成 Excel”，而在以下几类治理问题：

| 难点 | 说明 | 项目可承接能力 |
|---|---|---|
| 指标口径复杂 | 同一指标可能涉及会计科目、业务品种、客户类型、担保方式、行业、地区、五级分类等多维过滤 | 建立指标口径知识库和结构化规则卡 |
| 数据源分散 | 信贷、核心、财务、总账、客户、押品、资金、同业、理财、卡系统等都可能参与 | 建立报表字段到源系统字段的数据血缘 |
| 手工补录仍存在 | 部分低频、机构特色或治理未完善字段可能依赖人工补录 | 建立补录字段清单、责任人、凭证和复核记录 |
| 校验规则多 | 包括表内勾稽、表间一致性、跨期波动、与 EAST/客户风险/一表通明细比对 | 建立规则库、校验执行记录和差错闭环 |
| 版本变更频繁 | 每年制度、表样、填报说明、机构范围、时间表都可能调整 | 建立版本差异识别、影响分析和任务生成 |

## 8. 对本项目主线的影响

原项目主线偏向：

```text
监管发文上传
  -> 条款抽取
  -> 语义识别
  -> 影响分析
  -> 规则卡片/工单
```

围绕一表通和 1104 重构后，建议调整为：

```text
监管制度与报表版本管理
  -> 报表目录/机构范围/频度时限解析
  -> 表样与填报说明结构化
  -> 指标口径与字段映射
  -> 一表通明细数据/1104指标加工映射
  -> 数据质量校验与差错闭环
  -> 报送任务运营与审核反馈
```

对应产品模块建议：

| 模块 | 目标 | 首期可做内容 |
|---|---|---|
| 制度与版本库 | 管理年度通知、附件、表样、填报说明 | 导入 2025 年附件，展示版本、来源、适用范围 |
| 报表目录库 | 管理报表编号、名称、类别、机构范围、口径、频度、时限 | 结构化附件 1、附件 2、附件 3 |
| 表样结构化 | 管理表格行列、指标、单元格、填报说明 | 一期先选 G21、G24、G25、G27、G31 资金同业相关报表做样板 |
| 数据映射 | 建立报表指标到报送字段、数据集市字段、源系统字段和维度字段的映射 | 使用 `reg_reporting_items`、`data_field_catalog`、`reporting_item_lineage` 作为主线资产 |
| 校验规则 | 管理表内、表间、跨期、跨体系校验 | 将填报说明中的口径和勾稽关系沉淀为规则卡 |
| 报送日历 | 生成年度报送任务、上报截止、审核截止和预警 | 基于附件 3 建立 2025 年任务日历 |
| 一表通衔接 | 建立 1104 指标与一表通明细数据/可信区的关系 | 先做概念模型和字段映射样板，不急于假设完整监管接口 |
